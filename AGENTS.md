## Hard session rules

### No attribution in repository artifacts

NEVER append a "Generated by Codex" (or similar self-attribution)
footer/signature, and NEVER add a `Co-Authored-By:` trailer unless explicitly
requested, to ANY repository artifact: commit messages, GitHub issue/PR comment
bodies, PR descriptions, release notes, changelog entries, or documentation.
Write as normal project/engineering communication. This has recurred 6+ times
across sessions despite being flagged every time.

This is model-generated text, not something injected by a hook, git config,
MCP integration, or any other tool-level mechanism (confirmed by direct
investigation: no hooks configured globally or per-project, no commit
template, no `core.hooksPath`, no GitHub Actions workflow touches comment
text). Treat it as a standing output-quality rule to self-check on every
piece of content you write, not a one-time bug to fix -- there is no config
toggle that makes this reliable instead of vigilance.

**Before drafting is not enough -- check the actual content before it leaves
the local workspace.** Before running `gh issue comment`, `gh pr create`,
`gh pr comment`, `git commit`, or writing any doc/changelog file, re-read the
exact text you are about to send/write and strip any self-attribution or
`Co-Authored-By` line yourself. Do not rely solely on the post-hoc sweep
below to catch it after the fact.

After ANY task that touched GitHub issues/PRs/commits, also run the sweep as
a backstop -- across every surface, not just issue comments (PR bodies and PR
review comments have separately carried this too):
```
gh api repos/Jumpstile/teknoparrot-manager/issues/comments --paginate --jq '.[] | select(.body | test("Generated by|Codex|Co-Authored")) | .html_url'
gh api repos/Jumpstile/teknoparrot-manager/pulls/comments --paginate --jq '.[] | select(.body | test("Generated by|Codex|Co-Authored")) | .html_url'
gh pr list --repo Jumpstile/teknoparrot-manager --state all --json number,body --jq '.[] | select(.body != null) | select(.body | test("Generated by|Codex|Co-Authored")) | .number'
gh issue list --repo Jumpstile/teknoparrot-manager --state all --json number,body --jq '.[] | select(.body != null) | select(.body | test("Generated by|Codex|Co-Authored")) | .number'
```
Confirm every command returns nothing -- not just spot-check the issue(s) or
PR(s) you happened to touch this session. If anything is found, strip it
immediately (edit the comment/PR body via `gh api ... -X PATCH`); do not defer
cleanup to a later session.

NEVER post the back-and-forth debugging of a throwaway diagnostic script's own
bugs to an issue comment. An issue comment records only the confirmed root
cause/fix for the actual product bug -- never the iteration noise of fixing the
tooling used to investigate it.

This rule is also codified as a standing Team Jumpstile checklist item -- see
RELEASE-SAFETY-CHECKLIST.md section 8 ("AI attribution sweep") for the
procedural checklist form (forbidden examples, do-not-alter-technical-content
guardrail, and the per-issue/PR sweep required after every cleanup).

### Verify before acting

Every concrete claim from a code review, automated scan, or external analysis
must be verified empirically against the actual code before acting on it.
"The review said X" is not the same as "X is true." See LESSONS_LEARNED.md
(v0.99.24/v0.99.25 entries) for the two specific cases where this rule prevented
reintroducing a real bug.

## Key conventions

- Version bump required on every meaningful change set.
- All file writes use BOM-less UTF-8: `(New-Object System.Text.UTF8Encoding $false)`.
- All `Get-ChildItem` calls use `-LiteralPath`.
- Backup before every destructive operation; abort the whole operation if backup fails.
- Safety over convenience -- never guess, never silently swallow errors.
- Numbered step-by-step output for every user-facing action.
- New persistent settings go into `Save-Config` once, not at each call site.
- Script must be pure ASCII (no Unicode anywhere). PS 5.1 reads BOM-less UTF-8 as
  Windows-1252; the last byte of U+2014 (em dash, E2 80 94) is 0x94, which
  Windows-1252 maps to U+201D (right double-quote, a string delimiter), causing
  parse errors. Use `--` for em dashes, `->` for arrows.
  Verify: `($bytes=[System.IO.File]::ReadAllBytes('TeknoParrot-Manager.ps1'); ($bytes | Where-Object { $_ -gt 127 }).Count)`
- `Split-Path -LiteralPath $x -Parent` throws in PS 5.1 -- use
  `[System.IO.Path]::GetDirectoryName()` instead. See LESSONS_LEARNED.md (v0.99.6).

## Patch versioning (introduced v0.99.1)

- Whole-number bumps: feature releases (v0.94, v0.95, ..., v0.99).
- Third segment: bug-fix-only releases (v0.99.1, v0.99.2, ...).
- A patch release still gets the full treatment: version bump in `$ScriptVersion`
  and the header comment, CHANGELOG entry, all doc version lines updated, wiki entry,
  tag + ZIP + GitHub release + prune-to-5.
- Patch releases do NOT need a full doc-sweep for new features/mode numbers -- by
  definition nothing user-facing changed except behavior that was already supposed to
  work correctly.

## Pre-commit quality gates

Full sequence with exact commands: RELEASE-SAFETY-CHECKLIST.md section 1.

1. **ASCII + parse check** -- zero non-ASCII bytes, zero parse errors.
2. **PSScriptAnalyzer** (Severity Error,Warning) -- use the project settings file:
   `Invoke-ScriptAnalyzer -Path TeknoParrot-Manager.ps1 -Severity Error,Warning -Settings PSScriptAnalyzerSettings.psd1`
   `PSScriptAnalyzerSettings.psd1` codifies all approved exclusions with rationale
   (including `PSAvoidUsingWriteHost`). Any surviving finding must be fixed or
   the settings file updated with documented rationale before committing.
3. **InjectionHunter** -- trace every finding to confirm whether the flagged input
   is actually attacker-controlled before dismissing as a false positive. A finding
   is never dismissed by label alone.
4. **Pester suite** -- must be 100% green. Fix regressions; do not adjust tests to
   match wrong behavior unless the behavior change was explicitly intended this round.
5. **Full manual deep scan** -- trace the actual logic of every function touched this
   round. See SECURITY.md for what to look for (path-traversal, swallowed errors,
   resource leaks, TOCTOU).
6. **Upstream compatibility safety review** -- for any round that touches how the
   script reads or writes GameProfiles. See RELEASE-SAFETY-CHECKLIST.md section 2.

## Codex delegation (mandatory handoff format)

Codex is onboarded separately per repository and has zero context from any other
repo or prior session. Every Codex handoff for this repository must include all
nine fields -- no exceptions, even when the task seems obvious:

1. **Repository name** -- `Jumpstile/teknoparrot-manager`
2. **Branch/state** -- branch to work on and current HEAD commit
3. **Relevant issue number** -- GitHub issue being addressed (if any)
4. **Exact task** -- specific, unambiguous description of what to do
5. **Files likely involved** -- list files Codex should read and/or modify
6. **Required tests** -- which tests must pass and how to run them
   (always: ASCII check, parse check, PSScriptAnalyzer with PSScriptAnalyzerSettings.psd1,
   Invoke-Pester -Path .\Tests\TeknoParrot-Manager.Tests.ps1)
7. **Safety constraints** -- what Codex must not do (feature freeze, no commits to
   main directly, no release artifacts changed without explicit instruction, etc.)
8. **Definition of done** -- concrete, verifiable completion criteria
9. **Whether Codex is allowed to modify files** -- state read-only vs. read-write explicitly

Do not assume Codex has read AGENTS.md, the issue thread, or any prior exchange.
