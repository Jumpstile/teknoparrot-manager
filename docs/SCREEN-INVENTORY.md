# Screen inventory

Every screen family in TeknoParrot Manager: how it is drawn, how it reads input, how it copes with window size and display scaling (DPI), and what has been proven. The point is to see at a glance which screens are measured against the window and which are not.

Function names are given instead of line numbers so the table stays correct as the script changes. Proof means an automated test with a fake console. Nothing here has been run on a real Windows console or at a real display scaling.

## Legend

1. Width: `Get-ConsoleContentWidth`  treats any host value above 240 as bogus and returns 110, then falls back to BufferSize and `[Console]::WindowWidth`; height: `Get-ConsoleContentHeight` falls back to 25.
2. Text: `Write-TpmText` rewraps to `min(console, 100)` on every call, with hanging indent and optional long-path breaking; `Write-TpmResetRestoreText` uses the console width only; main menu and progress bars compose exact-width rows instead.
3. Input: `Read-HostSafe` is the only prompt primitive and exits cleanly when stdin ends; "ReadKey" means `[Console]::KeyAvailable`/`ReadKey` polling with an `IsInputRedirected` or exception fallback to `Read-HostSafe`.
4. Proof: all evidence is Pester with injected or mocked console geometry (widths 40-200, heights 8-30); nothing in this inventory was run on a real PC.
5. Not proven by any test: real conhost or Windows Terminal resize and scrollback, 100/125/150/200 percent DPI, font cell widths, WinForms painting, and screenshots.
